## 5. Telegram-бот (bot.py) — подробная логика

### 5.1. Режимы работы бота

Бот работает в двух режимах:

**Режим A — Прямое сообщение боту (приватный чат с владельцем)**
- Владелец отправляет фото напрямую боту
- Бот сразу начинает обработку

**Режим B — Чтение канала (будущее)**
- Бот подписан на канал `@FarhadAdigyuzelov`
- Новый пост → бот автоматически начинает обработку
- Реализуется через `ChatMemberUpdated` или пересылку

Начинаем с режима A. Режим B добавляется позже.

## 6. Пайплайн поиска (pipeline.py) — 7 шагов

### Шаг 1: SerpAPI Google Lens — двойной поиск

```
Входные данные:
  ─ source_photo: путь к фото товара
  ─ caption_data: {brand, type, material, ...} из подписи

                    ┌──────────────────────┐
                    │  Загрузка фото       │
                    │  SerpAPI Image API   │
                    │  POST /image         │
                    │  → image_id          │
                    └──────────┬───────────┘
                               │
              ┌────────────────┼────────────────┐
              │                                  │
              ▼                                  ▼
   ┌──────────────────┐              ┌──────────────────┐
   │ Поиск 1:         │              │ Поиск 2:         │
   │ Только по фото   │              │ Фото + текст     │
   │                  │              │ q="{brand} {type} │
   │ engine=google_   │              │    {material}"   │
   │ lens             │              │                  │
   │ type=visual_     │              │ (только если     │
   │ matches          │              │  brand известен) │
   └────────┬─────────┘              └────────┬─────────┘
            │                                  │
            └──────────┬───────────────────────┘
                       │
                       ▼
            ┌──────────────────┐
            │ Объединение      │
            │ Дедупликация     │
            │ по URL           │
            │ → unique_matches │
            └──────────────────┘

Выход: список из ~20-50 уникальных кандидатов
```

Важно из опыта проекта:
- Чистый поиск по фото НЕЛЬЗЯ удалять — текст может подтянуть неправильный товар того же бренда
- Текстовый запрос формируется: `"{brand} men's {color} {type}"` на английском
- Параллельно оба запроса через `asyncio.gather`

### Шаг 2: Скачивание и предварительное ранжирование

```
Для каждого кандидата (топ-20):
  1. Скачать thumbnail/image
  2. Сохранить в assets/search/{job_id}/candidate-{N}.jpg
  3. Отфильтровать:
     ─ Битые картинки (< 3 КБ)
     ─ Не-изображения (content-type != image/*)

Будущее (FashionSigLIP):
  ─ Вычислить эмбеддинг исходного фото
  ─ Вычислить эмбеддинг каждого кандидата
  ─ Cosine similarity → ранжирование
  ─ Отсечь кандидатов с similarity < 0.3
  ─ Передать топ-8 на AI-ревью

Сейчас (без FashionSigLIP):
  ─ Берём первые 8 кандидатов
  ─ Передаём на AI-ревью
```

### Шаг 3: AI-ревью — Gemini Flash (быстрое)

```
Отправляем в Gemini 3.8 Flash через ai.starimg.ru:
  ─ Изображение 1: исходное фото
  ─ Изображения 2-9: топ-8 кандидатов
  ─ Промпт: сравни конструкцию (силуэт, воротник,
    застёжка, карманы, фактура, цвет)

Ответ (JSON):
  ─ selected_result_numbers: [1, 3]    # лучшие кандидаты
  ─ match_status_ru: "вероятное совпадение"
  ─ confidence_0_100: 78
  ─ characteristics: {цвет, тип, воротник, застёжка, ...}
  ─ comparison_ru: "силуэт совпадает, но воротник отличается"
  ─ uncertainties_ru: ["точная модель не подтверждена"]
```

### Шаг 4: AI-финализация — GPT Sol (точное)

```
Отправляем в GPT 6.1 Sol через ai.starimg.ru:
  ─ Исходное фото + лучшие кандидаты
  ─ Результат Gemini для перепроверки
  ─ Данные из подписи владельца

GPT должен:
  ─ Независимо проверить вердикт Gemini
  ─ Исправить ошибки если есть
  ─ Выбрать до 4 лучших фото
  ─ Написать описание в стиле магазина
  ─ Определить характеристики

Если Gemini и GPT расходятся:
  ─ Если разница в статусе (exact vs similar) → Claude Sonnet арбитр
  ─ Если разница только в деталях → берём GPT

Ответ (JSON):
  ─ product_name_ru: "Куртка из шерсти"
  ─ brand_ru: "Loro Piana"
  ─ description_ru: "2-3 предложения"
  ─ match_status: "probable_match"
  ─ confidence_0_100: 78
  ─ selected_result_numbers: [1, 3]
  ─ characteristics: {...}
```

### Шаг 5: Crawl4AI — извлечение данных со страницы

```
Если match_status == "exact_match" или "probable_match":
  ─ Берём URL лучшего кандидата
  ─ Crawl4AI загружает страницу
  ─ Извлекаем:
    ─ Все фото товара в высоком качестве
    ─ Название
    ─ Цену (для справки, не для магазина)
    ─ Материал и состав
    ─ Описание
    ─ Размерная сетка
  ─ Сохраняем фото в assets/products/{product_id}/

Если match_status == "similar_only" или "not_found":
  ─ Пропускаем скрапинг
  ─ Используем данные из подписи + AI-описание
  ─ Фото — только исходное от владельца
```

### Шаг 6: Генерация финальной карточки

```
GPT 6.1 Sol генерирует:
  ─ product_name_ru: краткое название
  ─ description_ru: 2-3 спокойных предложения
    (стиль ЦУМа, без выдуманных фактов)
  ─ characteristics: {
      цвет, материал, крой, застёжка,
      воротник, размеры
    }

Правила описания:
  ─ НЕ выдумывать материал, артикул и состав
  ─ НЕ утверждать точную модель без подтверждения
  ─ Если данных из подписи достаточно → использовать их
  ─ Если данные из Crawl4AI есть → приоритет у них
  ─ Тон: спокойный, премиальный, без восклицаний
```

### Шаг 7: Классификация по 28 категориям

```
Вход: тип товара, бренд, описание, характеристики

Алгоритм (classifier.py):
  1. Прямое совпадение:
     "куртка" → Куртки
     "пуховик" → Зимние куртки
     "лоферы" → Классическая обувь
     "худи" → Толстовки
     (маппинг из catalog-categories.json → includes)

  2. Если прямого совпадения нет:
     AI (GPT) определяет категорию из списка 29

  3. Валидация:
     ─ Результат ДОЛЖЕН быть одним из 29 id
     ─ Если AI вернул что-то другое → fallback "accessories"

Маппинг подтипов (из CATALOG_CATEGORIES.md):
  бомбер → jackets
  пуховик → winter-jackets
  полупальто → coats
  тренч → coats
  худи → hoodies
```

## 10. Полный flow: от фото до публикации

```
1. Владелец → отправляет фото + "Куртка Loro Piana. 100% шерсть. M-3XL"
                │
2. Бот → парсит подпись:
         brand="Loro Piana", type="куртка",
         material="100% шерсть", sizes=["M","L","XL","XXL","3XL"]
                │
3. Бот → "🔍 Начинаю поиск: Loro Piana куртка..."
                │
4. Pipeline Шаг 1 → SerpAPI Google Lens:
   ─ Поиск 1: только фото → 28 visual_matches
   ─ Поиск 2: фото + "Loro Piana men's wool jacket" → 22 matches
   ─ Дедупликация → 41 уникальный кандидат
                │
5. Pipeline Шаг 2 → Скачивание топ-20 thumbnails
   ─ Отфильтровано 3 битых → 17 валидных
   ─ Берём топ-8
                │
6. Pipeline Шаг 3 → Gemini Flash:
   ─ "Кандидаты 1 и 5 наиболее похожи по силуэту"
   ─ "Вероятное совпадение, 72%"
   ─ "Воротник совпадает, но цвет немного отличается"
                │
7. Pipeline Шаг 4 → GPT Sol:
   ─ Перепроверяет Gemini
   ─ "Согласен: вероятное совпадение, 78%"
   ─ "Кандидат 1 — Mr Porter, Loro Piana Wind Breaker"
   ─ Описание: "Лёгкая куртка из мягкой шерсти..."
                │
8. Pipeline Шаг 5 → Crawl4AI:
   ─ Загружает mrporter.com/...
   ─ Извлекает 4 фото в высоком качестве
   ─ Извлекает состав: "100% virgin wool"
   ─ Сохраняет в assets/products/42/
                │
9. Pipeline Шаг 6 → Финальная карточка:
   ─ Название: "Куртка из шерсти Loro Piana"
   ─ Описание: 2 предложения
   ─ Характеристики заполнены
                │
10. Pipeline Шаг 7 → Классификация:
    ─ "куртка" → category_id="jackets"
                │
11. Бот → отправляет карточку владельцу:
    ─ 4 фото (исходное + 3 с Mr Porter)
    ─ Подробная подпись
    ─ Кнопки: Подтвердить / Исправить / Отклонить
                │
12. Владелец → нажимает "✏️ Исправить"
    → "Цена 185 000 руб"
                │
13. Бот → обновляет price="185 000 ₽"
    → отправляет обновлённую карточку
                │
14. Владелец → нажимает "✅ Подтвердить"
                │
15. Бот → product.status = 'approved'
    → category 'jackets' has_products = True
    → "✅ Товар опубликован"
                │
16. Магазин → API отдаёт товар
    → Frontend показывает в каталоге
```

## 11. Обработка ошибок

```
┌─ SerpAPI не нашёл ничего ─────────────────────┐
│  → Бот: "❌ По фото ничего не найдено.         │
│    Попробуйте другое фото или добавьте         │
│    больше информации в подпись."                │
│  → Сохраняем job с error, не создаём карточку  │
└────────────────────────────────────────────────┘

┌─ AI не уверен в совпадении ───────────────────┐
│  → match_status = "similar_only"               │
│  → Карточка отправляется с предупреждением:    │
│    "⚠️ Точный товар не найден. Показаны        │
│     похожие модели. Описание составлено        │
│     по данным из подписи."                     │
│  → Фото — только исходное от владельца         │
│  → Владелец может подтвердить как есть          │
│    или отклонить                               │
└────────────────────────────────────────────────┘

┌─ Crawl4AI не смог загрузить страницу ─────────┐
│  → Используем thumbnail из SerpAPI             │
│  → Описание из AI без данных со страницы       │
│  → Предупреждение в карточке                   │
└────────────────────────────────────────────────┘

┌─ API-ключ закончился / ошибка ────────────────┐
│  → Бот: "⚠️ Сервис временно недоступен.        │
│    Попробуйте позже."                          │
│  → Лог ошибки в search_jobs.error              │
│  → Retry через 5 минут (до 3 попыток)          │
└────────────────────────────────────────────────┘

┌─ Gemini и GPT дали разные статусы ────────────┐
│  → Gemini: "exact_match", GPT: "similar_only"  │
│  → Вызываем Claude Sonnet как арбитра          │
│  → Claude видит все те же фото + оба вердикта  │
│  → Его решение финальное                       │
│  → Если Claude тоже не уверен → "similar_only" │
└────────────────────────────────────────────────┘
```

## 12. Безопасность

- API-ключи ТОЛЬКО в `.env`, никогда в коде/git/frontend
- Бот отвечает ТОЛЬКО владельцу (проверка `OWNER_CHAT_ID`)
- Frontend НЕ делает запросов к SerpAPI/OpenAI напрямую
- Все AI-запросы через серверный код
- Rate limiting на API-сервере
- Фото хранятся локально, не на внешних хостингах (в production)
